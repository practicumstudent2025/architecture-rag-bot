# Описание процесса создания базы знаний

## Структура папок проекта

```
architecture-rag-bot/
├── raw_pages/              # Исходные HTML страницы, скачанные с Fandom Wiki
├── cleaned_texts/          # Очищенные тексты без HTML разметки
├── knowledge_base/         # Финальная база знаний с замененными терминами
├── download_pages.py       # Скрипт для скачивания страниц
├── clean_texts.py          # Скрипт для очистки HTML
├── replace_terms.py        # Скрипт для замены терминов
└── terms_map.json          # Словарь замен терминов
```

### Назначение папок

#### `raw_pages/`
- **Назначение**: Хранит исходные HTML-файлы, скачанные с сайта starwars.fandom.com
- **Содержимое**: 
  - `*.html` - HTML страницы с полной разметкой
  - `downloaded_pages.json` - список успешно скачанных страниц
- **Использование**: Временное хранилище для исходных данных

#### `cleaned_texts/`
- **Назначение**: Промежуточное хранилище очищенных текстов
- **Содержимое**:
  - `*.txt` - текстовые файлы без HTML разметки
  - `cleaned_files.json` - список обработанных файлов
- **Использование**: Промежуточный этап обработки перед заменой терминов

#### `knowledge_base/`
- **Назначение**: Финальная база знаний для RAG-бота
- **Содержимое**:
  - `*.txt` - 31 документ с замененными терминами
  - `terms_map.json` - словарь всех замен
  - `README.md` - описание базы знаний
- **Использование**: Используется для создания векторного индекса в RAG-пайплайне

## Логика работы скриптов (шаг за шагом)

### Шаг 1: Скачивание страниц (`download_pages.py`)

**Цель**: Получить исходные HTML страницы с Fandom Wiki

**Процесс**:
1. **Инициализация**:
   - Определяет список из 31 страницы для скачивания
   - Создает папку `raw_pages/` если её нет
   - Устанавливает базовый URL: `https://starwars.fandom.com/wiki/`

2. **Для каждой страницы**:
   - Формирует полный URL (например: `https://starwars.fandom.com/wiki/Darth_Vader`)
   - Отправляет HTTP GET запрос с User-Agent заголовком
   - Получает HTML содержимое страницы

3. **Сохранение**:
   - Сохраняет HTML в файл `raw_pages/{page_name}.html`
   - Делает паузу 1 секунду между запросами (чтобы не перегружать сервер)

4. **Результат**:
   - 31 HTML файл в папке `raw_pages/`
   - Файл `downloaded_pages.json` со списком скачанных страниц

**Пример работы**:
```
Скачиваю: https://starwars.fandom.com/wiki/Darth_Vader
Сохранено: raw_pages/Darth_Vader.html
...
Скачано страниц: 31/31
```

---

### Шаг 2: Очистка текстов (`clean_texts.py`)

**Цель**: Извлечь чистый текст из HTML, убрав всю разметку

**Процесс**:
1. **Инициализация**:
   - Читает все `.html` файлы из папки `raw_pages/`
   - Создает папку `cleaned_texts/` если её нет

2. **Парсинг HTML**:
   - Использует библиотеку BeautifulSoup для парсинга HTML
   - Удаляет ненужные элементы: `<script>`, `<style>`, `<nav>`, `<footer>`, `<header>`, `<aside>`

3. **Извлечение контента**:
   - Ищет основной контент статьи (обычно в `<div class="mw-parser-output">`)
   - Извлекает заголовок страницы (`<h1>`)
   - Извлекает текст из параграфов (`<p>`), заголовков (`<h2>`, `<h3>`) и списков (`<li>`)

4. **Фильтрация**:
   - Пропускает слишком короткие фрагменты текста (менее 20 символов)
   - Объединяет все части в один текст с разделителями `\n\n`

5. **Сохранение**:
   - Сохраняет очищенный текст в `cleaned_texts/{page_name}.txt`
   - Создает список обработанных файлов в `cleaned_files.json`

**Пример работы**:
```
Очищено: Darth_Vader.html -> Darth_Vader.txt
Очищено: Luke_Skywalker.html -> Luke_Skywalker.txt
...
Очищено файлов: 31/31
```

**Результат**: 31 текстовый файл без HTML разметки

---

### Шаг 3: Замена терминов (`replace_terms.py`)

**Цель**: Заменить все термины Star Wars на вымышленные названия согласно словарю

**Процесс**:
1. **Загрузка словаря**:
   - Читает файл `terms_map.json`
   - Собирает все замены из всех категорий (characters, organizations, locations, technologies, concepts)
   - Сортирует замены по длине (сначала длинные, чтобы избежать частичных замен)

2. **Обработка каждого файла**:
   - Читает текст из `cleaned_texts/{filename}.txt`
   - Применяет замены с помощью регулярных выражений
   - Учитывает различные варианты написания (с заглавной, строчной буквы)

3. **Механизм замены**:
   - Использует регулярное выражение `\b{термин}\b` для поиска целых слов
   - Учитывает регистр (заменяет "Darth Vader" → "Xarn Velgor", "darth vader" → "xarn velgor")
   - Применяет замены в порядке убывания длины термина

4. **Сохранение**:
   - Сохраняет обработанный текст в `knowledge_base/{filename}.txt`
   - Копирует словарь замен в `knowledge_base/terms_map.json`

**Пример замен**:
```
Исходный текст: "Darth Vader was a Sith Lord who used the Force"
После замены: "Xarn Velgor was a Shadow Lord who used the Synth Flux"
```

**Результат**: 31 документ с замененными терминами в папке `knowledge_base/`

## Полный процесс выполнения

### Команды для запуска:

```bash
# Шаг 1: Скачать страницы
python3 download_pages.py

# Шаг 2: Очистить тексты от HTML
python3 clean_texts.py

# Шаг 3: Заменить термины
python3 replace_terms.py
```

### Последовательность операций:

```
1. download_pages.py
   ↓
   raw_pages/*.html (31 файл)
   
2. clean_texts.py
   ↓
   cleaned_texts/*.txt (31 файл)
   
3. replace_terms.py
   ↓
   knowledge_base/*.txt (31 файл) + terms_map.json
```

## Словарь замен (terms_map.json)

**Структура**:
- `description` - описание словаря
- `source_universe` - исходная вселенная (Star Wars)
- `replacement_strategy` - стратегия замены
- `characters` - замены персонажей (11 терминов)
- `organizations` - замены организаций (6 терминов)
- `locations` - замены локаций (7 терминов)
- `technologies` - замены технологий (7 терминов)
- `concepts` - замены концепций (6 терминов)

**Всего замен**: 37 уникальных терминов

**Примеры замен**:
- Персонажи: "Darth Vader" → "Xarn Velgor"
- Организации: "Jedi" → "Aether Knights"
- Локации: "Tatooine" → "Desertia"
- Технологии: "Death Star" → "Void Core"
- Концепции: "The Force" → "Synth Flux"

## Итоговый результат

После выполнения всех скриптов получаем:

- **31 документ** в папке `knowledge_base/` с уникальными терминами
- **Словарь замен** `terms_map.json` для отслеживания всех замен
- **База знаний**, которую LLM не может "угадать" из обучающего датасета
- **Готовые тексты** для создания векторного индекса в RAG-пайплайне

Все документы сохраняют логику и стиль оригинального мира, но используют вымышленные названия, что гарантирует честную работу механизма RAG.
